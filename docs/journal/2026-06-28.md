## Technical highlights / decisions

- RFC 6238 verified against the reference vector (287082); follows the NENE2 recipe
  + the FT reference implementation.
- The MFA **challenge token is signed with a secret derived from (and distinct from)**
  the session secret, so it can never be presented as a session bearer token —
  asserted by a dedicated test. Short-lived (5 min), single-purpose.
- Code verification (which records failures for lockout) runs **outside** the
  business transaction, so a wrong code's failure count is never rolled back.
- Because login now always reads TOTP status, **12 login-exercising HTTP tests** got
  the TOTP tables added to their fixtures (avoids 500s).
- Terminology registered (entities, operationIds, problem slugs, audit events);
  `mfa_enabled` / `mfa_disabled` localized in the audit log (no raw slugs).

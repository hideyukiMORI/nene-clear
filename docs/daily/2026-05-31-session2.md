## What works end-to-end (verified by tests)

1. `PUT /admin/clear-settings` → sets `dunning_min_interval_days` per org — **new**
2. `POST /admin/clear-settings/test-upstream` → probes Invoice upstream, returns `{reachable: bool}` — **new**
3. `POST /admin/dunning-notices` (admin/member only):
   - Checks invoice is `issued`/`partially_paid` AND outstanding > 0 (ADR 0011 §4.1)
   - Checks minimum interval since last notice for the same invoice (default 7d; configurable)
   - Renders professional-tone template (ADR 0011 §4.4 — no coercive/false content)
   - Logs via `LogOnlyDunningMailer`; saves immutable `DunningNotice`; audit `dunning_sent`
   - Returns 422 with `next_allowed_at` if interval not elapsed — **new**
4. `GET /admin/dunning-notices` / `/{id}` — history list — **new**

## Key decisions

- **LogOnlyDunningMailer**: Phase 2 does not send actual email. `DunningMailerInterface` is the seam; a real `SmtpDunningMailer` plugs in as a future PR once operator SMTP config is added to ClearSettings.
- **ADR 0011 compliance**: eligibility check, min interval, self-collection boundary enforced in `SendDunningUseCase`. No auto interest. Template text reviewed for professional tone.
- **`InvoiceUpstreamClientInterface::getClient()`**: added to retrieve `recipientEmail` from Invoice. `FakeInvoiceUpstreamClient::addClient()` for test seeding.
- **ClearSettings UPSERT**: DELETE + INSERT pattern for SQLite/MySQL compatibility.

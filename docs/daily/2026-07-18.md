## CI job 名の衝突解消と required 締め増し

- **#366 / #367**（`497b172`）: `backend-ci.yml` と `frontend-ci.yml` が**両方 job 名 `check`** を持ち、required status check の context 名が衝突していた〔実測〕。`backend-check` / `frontend-check` へ rename。
- 🔴 **required 化した job 名の rename 罠**〔実測〕: rename PR は新名の check を emit し**旧 required `check` を出さなくなる**→ PR 自身が永久 BLOCKED になる chicken-and-egg。正順で解決 — PR作成→新名CI緑→**merge せず**→ hub が branch protection の required を PATCH →unblock 確認→self-merge。
- required contexts は `check` → **`[backend-check, frontend-check, postgres-migrate]`**〔実測: `gh api .../required_status_checks/contexts` で before/after 確認〕。`postgres-migrate` は PR で走る決定的ゲート（全 migration を PostgreSQL に適用）なので required 昇格。`close-referenced-issues` は **push 限定**（PR では走らない）ので候補外。`e2e` / `release-zip` は緑だが flakiness 観測後の締め増し枠に保留。
